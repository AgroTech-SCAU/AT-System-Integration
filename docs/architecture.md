# 系统架构

## 定位

AT-System-Integration 是通用机器人系统集成框架，而不是某一农业任务的专用软件

用户直接管理自己的机器人、功能系统和任务，具体应用示例与框架内核隔离

## 分层

```text
Electron / React
    |
    v
管理接口与运行核心
    |-- 机器人项目及配置管理
    |-- 能力注册与适配器映射
    |-- 整机安全模式和控制门控
    |-- 用户可配置业务 HSM
    |-- 行为树 BT 定义、执行与记录
    |
    +---- 业务 HSM -> BehaviorTree.CPP
                 |
                 v
             能力适配器
                 |
       ROS2 / SDK / 进程 / MCU 网关
                 |
                 v
           控制器和真实设备
```

GUI 是配置、任务设计与运行观察入口，不直接承担实时控制

整机安全模式管理控制权限、故障与安全停止，不允许业务层修改安全转移

用户可配置的业务 HSM 管理父子状态、事件、Guard 与 Entry、Do、Exit 生命周期，关联的动作交给 BT 执行

业务状态转换期间必须先取消正在执行的关联 BT 并确认设备停止，之后才能执行退出和进入动作

## 接入模型

接入包描述一个后端提供的能力、端口、参数、运行方式和执行入口

导入接入描述后可以在 GUI 中添加实例并自动生成能力映射，运行核心仍需确认代码部署、启用授权与后端就绪

对于陌生设备或不符合能力契约的软件，开发者需要自行编写适配器，GUI 不能在没有执行实现的情况下直接调用硬件

能力接口对用户显示为动作节点，任务节点使用有类型的输入输出数据，数据来源可从任务参数或上游动作结果中选择

## 任务执行

任务编辑器分别保存业务状态机和行为树结构，已发布 BT 使用不可变定义与当前系统快照

HSM 可以独立编排没有设备动作的逻辑状态，实际运行要求机器人配置已应用且系统就绪

工程可携带 HSM 结构，导入工程后的动作引用必须重新关联已发布的行为树

业务 BT 不替代设备侧碰撞保护、急停、看门狗及实时控制回路

未知执行结果不可自动认定成功，停止未确认时保留安全处理入口
