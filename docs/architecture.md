# 系统架构

## 定位

AT-System-Integration 是通用机器人系统集成框架，而不是某一农业任务的专用软件

用户直接管理自己的机器人、功能系统和任务，具体应用示例与框架内核隔离

## 分层

```text
Electron / React
    |
    v
管理接口与运行核心
    |-- 机器人项目及配置管理
    |-- 能力注册与适配器映射
    |-- 整机安全模式和控制门控
    |-- 用户可配置业务 HSM 主执行器
    |-- ROS 2 任务定义、发现及原生通信
    |-- 可选行为树 BT 定义与执行
    |
    +---- 业务 HSM -----> ROS 2 Action / Service / Topic
              |
              +------------> 可选 BehaviorTree.CPP
                                      |
                                      v
                                   能力适配器
                                      |
                                SDK / 进程 / MCU 网关
                                      |
                                      v
                                控制器和真实设备
```

GUI 是配置、任务设计与运行观察入口，不直接承担实时控制

整机安全模式管理控制权限、故障与安全停止，不允许业务层修改安全转移

用户可配置的业务 HSM 管理父子状态、事件、Guard 与 Entry、Do、Exit 生命周期，三个阶段可直接绑定 ROS 2 通信任务，也可以选用已发布的 BT

业务状态转换期间先取消正在执行的 Action 或关联 BT，再执行退出和进入动作，取消未确认时禁止继续转换

## 接入模型

接入包描述一个后端提供的能力、端口、参数、运行方式和执行入口

导入接入描述后可以在 GUI 中添加实例并自动生成能力映射，运行核心仍需确认代码部署、启用授权与后端就绪

对于已经提供 ROS 2 Topic、Service 或 Action 的后端，用户可直接在通信任务页面填写或扫描接口并配置字段，无需新增能力适配器

对于仅提供原生 SDK 或非 ROS 2 接口的设备，仍然需要由开发者提供 ROS 2 桥接节点或已有适配器，GUI 不能凭空控制设备

能力接口对用户显示为动作节点，任务节点使用有类型的输入输出数据，数据来源可从任务参数或上游动作结果中选择

## 任务执行

任务编辑器分别保存 HSM、ROS 2 通信任务和可选行为树，已发布 BT 仍使用不可变定义与当前系统快照

Service 等待的是服务响应，不等同于实际运动完成，Topic 发布一次也不提供完成确认，需要反馈时应优先使用 Action 或后续订阅任务

持续发布话题在状态退出时发送独立配置的停止消息，底层控制器仍应配置通信看门狗

HSM 可以在两种受控模式下运行

- 传统运行模式需要机器人配置已应用且系统就绪，支持原有 BT 和 ROS 2 通信任务
- 独立 ROS 2 模式面向空白机器人，要求传统运行核心已停止、用户确认实体安全保护，且状态机只关联 ROS 2 通信任务

工程可携带 HSM 结构，导入工程后应重新检查相关 ROS 2 任务与已发布行为树的引用及目标系统

业务 BT 不替代设备侧碰撞保护、急停、看门狗及实时控制回路

未知执行结果不可自动认定成功，停止未确认时保留安全处理入口
