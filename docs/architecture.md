# 系统架构

AT-System-Integration 面向开发者，把独立子系统接入机器人工程，再通过任务、层级状态机和行为树组织工作流

首次接入见[操作指引](interactive-guide.md)，本文说明配置对象之间的关系、运行职责和工程恢复方式

## 配置对象之间的关系

| 对象 | 内容 | 用途 |
| --- | --- | --- |
| 机器人工程 `robot-profile` | 机器人、子系统工作区、任务、状态机与行为树定义 | 保存并重新打开整个集成项目 |
| 子系统 ROS2 工作区 | 源码工作区、安装目录或导入的接口文件 | 提供离线接口定义与依赖资源 |
| 执行环境 | 子系统使用的 Python、工作区 setup 和接口类型支持 | 在对应工作区环境中执行通信与计算 |
| 启动模块 | 节点、组件、普通进程或已有 launch 的启动声明 | 描述启动依赖、提供接口与健康条件 |
| 任务 | 通信或计算方式、字段映射、输入输出契约与完成条件 | 提供可复用的单项操作 |
| 工作流 | HSM 状态层级与转换，或 BT 节点与子树 | 组合任务并对接数据 |
| 能力接入包 | 后端能力、端口、参数、运行方式与适配器入口 | 将已有 SDK 或设备能力接入能力运行核心 |

一个子系统可同时提供接口定义、执行环境和启动模块，这些对象分别服务于设计、通信执行和设备启动

子系统源码保持独立，外部机器人工程引用其资源和启动声明，运行台按依赖组合模块，业务工作流复用这些声明

集成软件只解释通用配置、执行生命周期和数据契约；具体机器人、业务算法、作业策略及业务资产格式由工程或子系统负责

## 运行职责

```text
Electron / React
    |
    v
Python Agent
    |-- robot-profile 与配置应用、恢复
    |-- 业务层级状态机 HSM
    |-- 任务定义、接口资源与数据契约
    |-- 执行环境与启动模块管理
    |-- 控制授权、资源互斥与停止核对
    |
    +---- 业务 HSM -----> ROS 2 通信与计算任务
              |                    |
              v                    v
       BehaviorTree.CPP      按工作区隔离的 Python / ROS 2 子进程
              |
              +---- ROS 2 任务或能力适配器
                                  |
                           子系统与真实设备
```

GUI 提供配置、任务设计与运行观察，Python Agent 管理定义、授权、资源和执行生命周期，设备控制器负责运动周期、碰撞保护、急停与通信看门狗

HSM 管理业务状态与事件，BT 管理任务内部的执行顺序和分支，整机安全模式独立管理控制权限、故障与安全停止，业务层遵循这些安全门控

HSM 的 Entry、Do、Exit 可关联直接任务或已发布 BT，状态转换和数据连接规则见[通用任务架构](task-architecture.md)

## 机器人工程与配置

`robot-profile/robot.json` 是工程定义的存储入口，SQLite 用作本机编辑与索引缓存，运行历史和设备停止记录保留在 Agent 状态目录

| 操作 | 配置处理 | 启动行为 |
| --- | --- | --- |
| GUI 打开工程 | 先读取定义，再选中空白机器人或安全应用已配置的能力系统 | 设备与工作流等待运行操作 |
| 使用 `--profile` 启动 Agent | 在提供管理接口前应用指定工程中已配置的能力系统，空白工程只选中 | 设备与工作流等待运行操作 |
| 重开同一已生效工程 | 沿用有效配置，保留恢复入口 | 继续显示已有恢复状态 |
| 切换配置 | 要求当前任务、操作和进程均已确认停止 | 配置应用完成后再准备运行 |

`--profile` 配置应用失败会阻止此次 Agent 启动，已有未确认记录继续保留，供后续核对

## 接入模型

| 子系统提供的接口 | 接入方式 |
| --- | --- |
| ROS 2 Topic、Service、Action | 导入工作区或接口文件，定义直接 ROS 2 任务，用于 HSM 或 BT |
| 原生 SDK 或非 ROS 2 接口 | 提供 ROS 2 桥接节点，或通过能力接入包和适配器暴露操作 |

离线扫描读取接口类型定义与依赖，并列出能够静态确定的通信端点候选，类型与实际通信名称分别配置

开发者确认无法静态确定的命名空间、重映射和动态端点，在线发现用于核对运行中的实际名称

能力接入包导入后可添加实例并生成能力映射，运行前还需完成代码部署、启用授权与后端就绪配置

## 按需准备与启动

各子系统可指定不同的 Python 和工作区 setup，接口定义供离线设计使用，执行环境负责加载实际类型与依赖，加载环境和启动设备分别执行

运行准备依次处理工作流定义、数据对接、接口依赖与启动计划，随后加载所需环境、核对模块入口和类型支持，最后按依赖顺序启动模块并依据接口与健康条件判断就绪

任务可选择由运行台管理模块，或使用外部已启动的接口，外部模式跳过提供模块的自动选择与启动，仍需通信环境、类型支持、控制授权和停止确认

## 执行模式

| 模式 | 条件 | 可用行为 |
| --- | --- | --- |
| 能力系统模式 | 机器人配置已应用，系统就绪 | 能力节点、ROS 2 任务及组合行为树 |
| 独立 ROS 2 模式 | 空白机器人，能力运行核心停止，已确认实体安全保护 | 直接 ROS 2 任务，以及由 ROS 2 任务和流程控制节点组成的行为树 |

包含 `Capability_` 节点的树需要能力系统就绪，使用能力适配器的已发布定义还需匹配有效系统快照

结果为 UNKNOWN 或停止未确认时，保留台账和核对入口，确认停止后才能继续相应操作
