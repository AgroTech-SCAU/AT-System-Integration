# 通用任务架构

## 分层职责

| 层级 | 职责 | 开发者操作 |
| --- | --- | --- |
| 系统 HSM | 运行状态、模式、故障处理与安全停止 | 查看当前状态、请求受控切换 |
| 任务 BT | 顺序、选择、子树、条件与动作流程 | 可视化编辑、校验、发布与运行 |
| 能力接口 | 设备和软件能力的输入、输出、类型与资源要求 | 注册契约、选择兼容后端 |
| 适配器 | 执行具体功能并报告状态 | 接入独立的实现 |

系统层沿用运行核心已有的模式与门控逻辑，不提供第二个与行为树重复的任务编辑器

允许设备适配器内部使用自己的局部状态机，但它应以能力操作的方式接受任务调用，不得绕开系统级停止与故障处理

## 从空白机器人开始

1. 在总览新建空白机器人
2. 进入系统搭建，导入需要的接入包并添加后端实例，或暂时保留空配置
3. 可以立即进入任务编排新建纯逻辑行为树；接入后端前也能编辑与保存草稿
4. 准备运行时才需要保存、校验并在停止态应用系统配置
5. 任务初始只有一个通用 Sequence 和用于占位的 AlwaysSuccess，不包含任何行业专属节点
6. 为当前任务添加 `target_speed`、`timeout` 等自己定义的参数，支持字符串、布尔、整数和数值类型
7. 从已注册节点库选取功能节点，将其输入绑定到任务参数或前序节点输出
8. 保存草稿、静态校验、发布固定定义，再经过预检与系统门控后运行

一个机器人系统允许保存多份互不相关的任务草稿和定义，不需要从示例开始

## 三类数据

| 数据 | 作用域 | 示例 |
| --- | --- | --- |
| 系统配置 | 一个机器人实例 | 接入包、后端实例、能力绑定 |
| 任务参数 | 一个任务定义 | 速度、超时、模式、重试次数 |
| 任务运行变量 | 一次执行及其 Blackboard | 目标位姿、识别结果、执行状态 |

参数由当前任务文档的 `inputs` 声明，发布时生成任务清单并随行为树一同冻结

`node_id`、端口和变量映射属于当前任务，不应被框架硬编码为采摘字段

## 示例与迁移

番茄采摘位于 `examples/tomato_picker/`，可以在选择兼容系统后从示例模板读取，或复制为普通通用任务草稿

其 `approach_dz`、`calibration_offset_x`、标定资产和采摘记录均是该示例自身的业务配置，不会进入新的空白任务

为兼容旧的已发布采摘任务，保留旧版任务策略的读取和校验，但全新编辑的任务采用 `general` 策略

机器人系统工程包可携带任务草稿，重新导入后必须重新核对依赖及安全状态，不会自动赋予执行授权

## 运行安全边界

- 行为树发布必须经过真实节点模型、输入输出类型、端口来源与资源冲突检查
- 自定义任务不能通过 XML 任意跳过系统模式、停止确认和操作授权
- 含副作用动作的自动重入、重试和并行执行在当前阶段仍受限制
- 带目标循环的执行还受已发布的候选数量上限约束
- 任务草稿不改变正在执行的固定定义，配置切换必须在允许的安全状态执行

目前采用能力层 Mock 验证和已有 BehaviorTree.CPP 执行路径，不声称已经通过任意真机任务或物理仿真验证

## 离线编辑与模型迁移

- 缺少 C++ 执行器时，任务编辑器提供少量通用控制与逻辑节点，允许创建、编辑、保存和静态预览，不提供任何真实设备能力节点，也不允许发布或运行
- 安装真实执行器并应用系统配置后，需要明确执行「检查并匹配当前系统」，对原草稿进行新节点模型的结构和契约校验；验证不通过则不更改草稿
- 行为树发布与运行始终基于真实执行器、当前配置快照及安全门控，离线结构检查不视为正式运行验证
- 当前 GUI 的拖放操作只添加节点到所选控制结构，节点位置移动不改变执行顺序；端口来源选择生成标准 Blackboard 映射，并受后端校验
