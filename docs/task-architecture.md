# 通用任务架构

## 三层职责

| 层级 | 管理内容 | 用户操作 |
| --- | --- | --- |
| 安全控制模式 | 待命、自动、手动、标定、故障、急停及设备授权 | 确认真实设备条件，不能修改或绕过安全门控 |
| 业务层级状态机 HSM | 父子状态、初始状态、事件、Guard、Entry、Do、Exit | 可视化定义业务阶段与状态转换 |
| 任务行为树 BT | 顺序、选择、动作、条件、数据绑定及子树 | 创建任务并绑定已有能力 |

HSM 不替代设备控制器，不参与运动控制周期

一个机器人可以定义多个独立的状态机，状态机与能力适配器均不绑定某个具体行业模板

## HSM 与 BT 如何协同

1. 在任务编排的行为树编辑器中创建、校验并发布行为树
2. 在层级状态机中建立根状态、子状态、初始子状态与事件转换
3. 给状态关联已发布的行为树，按需分配 Entry、Do、Exit
4. 在运行调试中确认系统就绪，再手动启动业务状态机
5. 发送事件后，运行核心判断 Guard 并选择转换目标
6. 若有正在运行的 Do，必须先取消并确认停止，之后才执行 Exit 和目标状态的 Entry
7. 进入目标叶状态后运行 Do，Do 完成可以产生 completed 或 failed 事件
8. 停止状态机时先停止关联动作，遇到未知结果或未确认停止则保留异常状态

Do 关联的行为树在状态进入时执行一次，其持续过程由 BT 自身维护，不会在每个状态检查周期重复启动

Guard 支持始终允许、等于、不等于、大于、小于及已声明的简单状态变量，不接受任意表达式或动态执行代码

## 工程隔离

空白机器人可以不连接任何后端就创建状态机和行为树，配置与发布授权仅在当前机器人的有效系统快照上完成

工程导出保存 HSM 状态层级、转换和变量，导入后因已发布行为树身份可能变化，Entry、Do、Exit 引用必须重新选择

番茄采摘仅作为示例，其他机器人不默认拥有采摘参数或工作流程
