# 通用任务架构

每个机器人可定义多个独立状态机，单项操作保存在任务库中，状态机与行为树按不同粒度组合这些操作

## 选择任务的组织方式

| 层级 | 管理内容 | 用户操作 |
| --- | --- | --- |
| 安全控制模式 | 待命、自动、手动、标定、故障、急停及设备授权 | 确认真实设备条件，业务流程遵循安全门控 |
| 业务层级状态机 HSM | 父子状态、初始状态、事件、Guard、Entry、Do、Exit | 可视化定义业务阶段与状态转换 |
| 任务行为树 BT | 顺序、选择、动作、条件、数据绑定及子树 | 组合 ROS 2 任务或已接入能力 |

状态机描述业务阶段，行为树适合表达阶段内部的顺序、选择和子树复用，简单阶段可直接关联 ROS 2 通信或计算任务，运动控制周期由设备控制器负责

运行台先核对保存的定义与依赖，再准备所需环境和模块，空白机器人的独立 ROS 2 模式也支持不含 `Capability_` 节点的行为树，配置与运行条件见[系统架构](architecture.md)

## 定义状态生命周期

| 阶段 | 执行时机 | 典型关联 |
| --- | --- | --- |
| Entry | 进入所属状态时执行 | 直接任务或已发布行为树 |
| Do | 进入所属状态后启动一次，在状态活动期间执行 | 直接任务或已发布行为树 |
| Exit | 正常转换离开所属状态时执行 | 直接任务或已发布行为树 |

活动路径上的父子状态可同时各有自己的 Do，任务或 BT 自身维护持续过程

根状态由文档的 `initial` 指定，每个复合状态通过自己的 `initial` 指定初始子状态，进入复合状态时沿这些字段确定活动叶状态，同级显示顺序与初始状态独立

事件从来源状态向父级查找匹配转换，Guard 使用已声明的状态变量，支持始终允许、等于、不等于、大于和小于，条件范围限定为这些比较操作

正常转换按以下顺序执行

1. 判断事件和 Guard，确定目标状态及双方保留的父状态
2. 停止离开状态的 Do，并确认停止
3. 由内向外执行离开状态的 Exit
4. 由外向内执行新进入状态的 Entry，再启动其 Do

保留在活动路径上的父状态持续活动，其 Do 保持运行

| 结束或异常情形 | 处理方式 |
| --- | --- |
| Do 成功 | 产生 `completed` 事件 |
| Do 失败 | 产生 `failed` 事件，无对应失败转换时显示待处理原因 |
| 进入成功或失败终态 | 确认活动行为停止并执行退出行为，再结束整个工作流 |
| 用户取消运行 | 停止关联行为并等待停止确认，跳过退出任务 |
| 结果未知或停止未确认 | 保留异常状态与核对入口，停止确认是继续操作的前提 |

## 选择任务的完成条件

| 通信方式 | 可确认的结果 | 配置要点 |
| --- | --- | --- |
| Service | 收到服务响应 | 运动是否完成由服务语义或后续反馈决定 |
| 发布一次 Topic 消息 | 消息已发布 | 需要完成反馈时使用后续订阅任务或 Action |
| 持续发布 Topic 消息 | 按配置频率持续发布 | 退出时发送独立配置的停止消息，设备侧配置通信看门狗 |
| Action | 目标执行终态与结果 | 按业务需要检查结果字段和停止确认 |

实体急停、碰撞保护和通信失联保护由设备侧实现，业务状态和 BT 通过确认结果决定后续操作

## 数据如何对接

HSM 使用流程变量连接阶段之间的数据，ROS 2 任务的输入输出端口连接实际消息字段

```text
来源消息字段 -> 来源任务输出 -> 流程变量 -> 当前任务输入 -> 目标消息字段
```

| 绑定位置 | 配置作用 |
| --- | --- |
| 任务 `input_bindings` | 将任务输入写入目标消息字段 |
| 任务 `output_bindings` | 将响应或消息字段提取为任务输出 |
| HSM 阶段绑定 | 将 Entry、Do、Exit 的任务端口连接到已声明的流程变量 |
| BT 黑板引用与子树端口 | 连接节点之间和子树边界上的数据 |

连接按类型、单位、坐标系、时间域和 ROS 字段结构检查兼容性，名称用于标识字段，单位或坐标转换通过显式计算任务完成，字段规范见[接入与执行契约](../contracts/README.md)

HSM 离线检查所有可达路径，必需输入需要初值或可靠的上游来源，实际使用时还需满足值范围与有效期要求

配置了 `stop_observation` 的 Action 可通过 `$stop_observation.after_ns`（`integer`）和 `$stop_observation.pose`（`json`）导出实测静止时刻与 TCP 位姿；位姿输出还需配置 `base_frame`、`tcp_frame`

输出取自任务结束时的关节稳定观测，后续任务可直接复用观测时间与位姿；仅在任务成功且停止确认成功时输出，原生 ROS 响应字段与 `$` 根响应映射保持原义

机器人业务计算通过工作区 `extension` 提供，入口为 `module:function`；函数接收 `(payload, stop_event)`，需要当前 ROS 时钟与 TF 查询时可额外声明关键字参数 `context`，使用 `context.now()` 和 `context.transform(parent, child, stamp=None)`

扩展在所选子系统环境中执行并返回 JSON 对象，配置文件路径通过任务的 `path_fields` 显式声明

### 行为树对外输出

主树的 OUTPUT 端口定义树级输出，嵌套子树先按映射写入根黑板，整树成功后执行器读取并校验这些最终值，TaskManager 确认停止后交给 HSM 更新绑定变量

未声明输出的树返回空对象，声明输出未产生或类型不符会使执行失败，失败、取消或停止未确认时保留原执行结果和核对状态，仅成功输出用于更新流程变量

内部动作结果保存在操作台账，外部流程只使用声明的根树输出，具体声明方式见[行为树执行器](../task_engine/README.md#根树输出边界)

## 编辑与迁移

| 编辑操作 | 保存内容 |
| --- | --- |
| 按名称新增状态 | 业务名称与工作台生成的内部标识 |
| 在层级列表拖放 | 父子关系或同级状态顺序 |
| 选择复合状态的初始子状态 | 该状态的 `initial` 字段 |
| 在画布拖动或自动排版 | 独立于状态结构保存的画布坐标 |
| 关联阶段行为 | Entry、Do、Exit 的任务或行为树引用 |

重新打开或迁移工程可恢复保存的结构与排列，目录工程恢复已有定义，工程包导入会重新建立任务身份和引用，导入后检查依赖、数据绑定及需要重新发布或关联的行为

编辑结构后，运行时仍按事件、Guard、安全模式和设备停止确认执行转换，操作入口见[操作指引](interactive-guide.md)
