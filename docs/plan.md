## 5 数据与交互约定

### 5.1 四类对象分开

| 对象 | 内容 | 原则 |
|---|---|---|
| 任务执行定义 | BehaviorTree.CPP XML、任务参数、项目策略与资产引用 | XML 是执行定义，不另存一套可独立执行的图 |
| 编辑草稿 | 由 XML 解析的类型化树、revision 与修改内容 | 临时编辑模型，通过统一转换生成 XML |
| 界面信息 | 坐标、缩放、折叠、显示名与编辑标识映射 | 独立布局文件，不影响控制和业务参数 |
| 发布与运行快照 | 不可变任务定义、模型摘要、系统绑定与资产摘要 | 启动使用固定内容，草稿修改不回写 |

原有 `harvest.xml`、`harvest.task.json`、`harvest.layout.json` 保持用途，若 P2 已建立方案目录，继续沿用，不重建任务存储

默认从原模板创建副本，不覆盖内置模板

### 5.2 编辑模型的最小字段

- TreeDocument 包含 main_tree_id、trees、revision 与节点模型摘要
- TreeDefinition 包含 tree_id、root_id、nodes 与显式子树端口契约
- TreeNode 包含 editor_id、registration_id、有序 children、ports 与必要的语义属性
- PortBinding 区分 typed_literal 和 blackboard_reference，输出端口必须绑定可写变量
- LayoutDocument 按 editor_id 保存位置、缩放与折叠，单独持有布局修订
- Diagnostic 包含 severity、code、tree_id、editor_id、port 和 reason

editor_id 是稳定编辑标识，复制生成新标识，改显示名不改标识

运行实例标识由发布映射和子树调用路径确定，两个调用同一子树不能混用状态或 operation_id

不得把任意编辑标识塞进执行器不接受的 XML 属性，使用已注册端口、认可名称或冻结的映射文件，并验证往返一致

### 5.3 节点与控件

| 类别 | 当前阶段约定 |
|---|---|
| 控制节点 | 至少支持实际已注册的 Sequence、Fallback，其他类型只有模型与执行语义明确时开放 |
| 条件节点 | 复用实际已注册条件与只读状态判断 |
| 动作节点 | 从能力注册表生成，绑定能力角色与兼容后端 |
| 装饰节点 | 从实际注册信息识别，有副作用动作的重试需项目策略明确允许 |
| 并发节点 | 若执行器已支持则接入，必须通过资源和 Blackboard 写入冲突校验 |
| 项目节点 | 保留 ForEachTarget 等既有节点的端口、有限循环和业务规则 |
| 子树 | 显式端口与作用域，禁止递归调用 |

画布采用自上而下布局，子节点执行顺序以有序 children 为准，同时提供上移、下移和序号显示

左侧节点库，中间树画布，右侧属性与绑定，下方校验与反馈，沿用 P2 主题、语言与等待组件

默认显示控制关系，选中节点后显示相关数据绑定，不把所有数据连线始终铺满画布

类型相同但坐标系不同必须使用已注册变换能力，禁止隐式忽略坐标系或编造标定

### 5.4 共享服务接口

优先扩展 P2 task-drafts 服务，建议提供下列统一入口，GUI 与 CLI 调用同一逻辑

| 入口 | 结果 |
|---|---|
| `describe_nodes()` | 实际注册类型、端口、子节点约束、能力关联与兼容摘要 |
| `parse_xml(xml, models)` | 支持范围内的 TreeDocument，或明确只读的未支持内容 |
| `serialize_xml(document, models)` | 标准 XML 与编辑标识映射 |
| `validate_tree(document, context)` | 节点/端口级 Diagnostic，不执行能力或获取控制权 |
| `publish_task(draft_id, revision, context)` | 不可变 definition_id、摘要与发布映射 |
| `start_published_task(definition_id, request_id)` | 经实际上下文再次校验后进入已有任务会话 |

当前系统配置、能力模型、任务定义和资产变化都会使旧校验结果失效，启动时不信任浏览器的已通过标记
