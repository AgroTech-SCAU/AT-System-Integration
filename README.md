# AT-System-Integration

面向通用机器人的图形化系统集成工作台，以层级状态机组织工作流程，以 ROS 2 话题、服务、动作连接实际功能模块，复杂逻辑可以选择使用行为树

## 安装与启动

在 Ubuntu 桌面中进入工程目录

```bash
./install.sh
./launch.sh
```

首次安装需要 Python、Node.js、npm、CMake、C++ 编译环境以及 Electron 图形依赖

连接 ROS 2 功能时，启动前还需要加载本机安装的 ROS 2 与机器人工作空间

```bash
source /opt/ros/humble/setup.bash
source /path/to/robot_ws/install/setup.bash
./launch.sh
```

## 配置机器人的工作流程

1. 创建空白机器人，或打开已有机器人
2. 进入任务编排，在 ROS 2 任务中新增通信任务
3. 选择 Topic、Service 或 Action，扫描在线接口或手动填写接口名称与消息类型
4. 读取消息字段，填写请求或消息内容，保存任务
5. 打开层级状态机，创建状态、设置父子关系和转换事件
6. 为状态选择进入任务、执行任务、退出任务，三个阶段都可以留空
7. 保存状态机，在系统和机器人准备就绪后启动，并在运行界面检查执行状态

空白机器人可以离线创建通信任务和状态机，只有实际运行才需要对应 ROS 2 节点在线

空白机器人可以在运行调试中使用独立 ROS 2 模式启动状态机，无需先创建传统执行适配器，启动前必须确认实体急停和通信失联保护可用

独立 ROS 2 模式只执行 ROS 2 通信任务，如果状态机引用了行为树，则需要使用已应用配置的传统运行模式

## ROS 2 通信方式

| 任务方式 | 运行方式 |
| --- | --- |
| Action | 发送一个目标，等待接受和最终结果，离开状态时请求取消并检查确认 |
| Service | 发送一次请求并等待响应，服务响应不一定等于实体动作完成 |
| Topic · 发布一次 | 发布一次消息后结束，不代表下游已经执行完成 |
| Topic · 持续发布 | 按设置频率发布，退出时停止周期发布并发送停止消息 |
| Topic · 等待消息 | 订阅话题，直到收到符合条件的消息或超时 |

设备自身仍应具备急停、失联保护和运动超时保护，工作台无法替代电机驱动器或控制器的底层安全机制

## 层级状态机与行为树

层级状态机是主编辑器，支持状态嵌套、指定初始子状态、事件转换、转换条件、画布拖动和缩放

每个状态提供三个可选阶段

- 进入任务：进入状态时调用一次
- 执行任务：状态激活后调用，可以等待反馈或持续执行
- 退出任务：离开状态前调用一次

执行任务结束后会产生完成或失败事件，可以连接到下一状态

如需重试、选择、复杂并行和多步骤子流程，可以在高级行为树编辑器中发布行为树，再将其关联到任一阶段

## 示例与独立教学

番茄采摘仅是可选机器人示例，相关参数不会注入空白机器人

右上角教学向导使用与正式工作台一致的界面和独立的模拟环境，不修改当前机器人数据，也不会操作真实硬件
