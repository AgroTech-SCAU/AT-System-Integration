# AT-System-Integration

面向机器人开发者的图形化系统集成工作台，以层级状态机组织流程，以 ROS 2 话题、服务和 Action 连接子系统，复杂子流程可使用行为树

## 安装与启动

在 Ubuntu 桌面中进入工程目录

```bash
./install.sh
./launch.sh
```

首次安装需要 Python、Node.js、npm、CMake、C++ 编译环境、libcurl 开发包和 Electron 图形依赖

打开已保存的机器人工程，也可以直接指定目录

```bash
./launch.sh --profile /absolute/path/to/robot-profile
```

机器人工程目录保存 robot.json 和 assets，软件本身与机器人工程分开管理；迁移工程后可重新打开，并在工程资源中修正外部依赖路径

启动工作台和打开工程不会自动启动子系统设备；在运行台提交运行请求后，软件才会检查工作流并准备所需模块

工程目录搬迁后，若提示本机安装与当前目录不匹配，请在新目录重新执行安装脚本

## 配置机器人的工作流程

1. 在机器人管理中创建机器人并选择空的工程存储目录，或打开已有 robot-profile 目录
2. 进入机器人页面的子系统 ROS2 工作区，为机械臂、视觉等子系统添加源码工作区、安装目录，或导入接口文件
3. 检查接口定义及依赖，补齐缺少的基础接口；接口编写和任务配置可以离线完成，无需先运行 ROS 节点
4. 在子系统工作区中配置执行环境，选择对应的 setup 文件和 Python，检查依赖后加载；各子系统的执行环境彼此隔离，无需把所有依赖装进工作台
5. 在启动模块中扫描并选择需要的节点、组件或子系统 launch，配置参数、依赖、提供的接口和必要的健康检查
6. 进入任务库，选择一个或多个不存在定义冲突的子系统工作区，再选择通信方式与接口类型，参数字段会自动显示
7. 配置实际通信名称、完成条件及输入输出，选择任务需要的启动模块，保存任务
8. 在流程编排中创建层级状态机，设置状态、父子关系、初始子状态和事件转换，为进入时、状态期间、离开时绑定任务或行为树
9. 将上游任务输出与下游任务输入映射到流程变量，核对数据类型、单位、坐标系和时间信息，保存并校验流程
10. 在运行台选择工作流，确认设备环境后运行，查看模块就绪状态、活动状态、任务反馈和执行记录

接口类型与通信名称是两项独立配置，例如 tomato_picker_interfaces/action/MoveArm 描述目标与结果的数据结构，而 /arm/move 是机器人实际提供的 Action 名称

通信名称可以从源码与启动配置中离线扫描，动态构造而无法解析的名称需要补充配置或手工确认；在线接口查看用于核对实际运行图，不是离线配置的前提

## 层级状态机与行为树

每个父状态独立指定初始子状态，进入父状态时沿初始路径进入叶状态；列表顺序用于组织和展示，不改变已经指定的初始状态

每个状态提供三个可选阶段

- 进入时调用一次进入行为
- 状态期间运行持续行为，成功或失败后产生对应事件
- 离开前停止持续行为并调用退出行为

普通状态可以等待事件，不会仅因没有行为就结束整个流程；需要结束时，将叶状态明确设为成功终态或失败终态

行为树用于重试、选择、并行和多步骤子流程，保存后可绑定到状态行为；结构与数据检查会说明具体节点、输入或引用的问题

## 通信方式与停止

| 任务方式 | 完成与停止语义 |
| --- | --- |
| 发布一次话题消息 | 发送后完成，不代表设备动作完成 |
| 持续发布话题消息 | 持续运行，退出或取消时停止发布并按配置发送停止消息 |
| 等待话题消息 | 收到满足条件的消息后完成，或等待超时 |
| Service | 等待响应并检查业务条件，请求取消不等于服务端停止执行 |
| Action | 等待最终结果，取消时核对终态及配置的停止反馈 |

Service 与 Action 可以配置停止核对服务；返回成功应表示设备或业务操作确已结束，不能只表示收到核对请求

操作结果未知或停止未确认时，运行台保留核对入口，确认后才解除相应资源占用；跨会话恢复还需要核对旧执行进程与设备状态

设备急停与通信失联保护由设备和控制器提供，工作台负责组织模块、任务、数据与运行状态
