# AT-System-Integration

## 独立教学工作区

右上角向导使用与正式工作台完全相同的页面、组件和后台接口，只切换到独立的教学数据上下文

进入时保留正式 GUI 的机器人选择、任务草稿、页面状态与未保存表单，教学过程中使用全屏模糊遮罩高亮真正需要操作的控件，完成高亮步骤并收到操作成功结果后自动进入下一步，不需要手动确认进度

教学后台通过独立的临时状态目录运行，只允许内置 Mock 适配器，所有进程管理动作均被替换为不会启动真实硬件的模拟管理器

结束教学后先安全结束模拟运行，再销毁教学状态并返回原来的 GUI，正式工程不发生修改

教学中的行为树发布与执行同样依赖正常安装的执行器，不会用虚假的运行成功代替真实管理结果

具体使用说明见 [`docs/interactive-guide.md`](docs/interactive-guide.md)

面向通用机器人的系统集成工作台

用户以机器人、功能后端和任务为中心完成日常操作，接入描述、能力契约、配置快照和行为树运行机制由框架负责管理

## 开始使用

在 Ubuntu 桌面进入工程目录后运行

```bash
./install.sh
./launch.sh
```

首次安装需要 Python、Node.js、npm、CMake、C++ 编译环境和 Electron 所需的图形依赖

安装文件保存在仓库忽略提交的 `.install/` 中

## 操作流程

1. 在机器人工作台创建空白机器人，或选择已有工程
2. 在系统搭建中点击添加系统，选择现有接入描述或导入自己的描述文件
3. 系统自动生成后端实例对应的能力映射，按需要填写设备参数并保存应用
4. 在任务编排中设计层级状态机与行为树，定义状态、事件、动作顺序和任务参数
5. 在运行调试中查看阻塞原因，确认系统和设备安全状态后启动任务
6. 在记录报告中查看运行历史与故障信息

空白机器人无需先接入设备就能创建和保存通用逻辑任务

番茄采摘仅是可选示例，示例参数与功能节点不会注入其他机器人

## 三个主要工作区

| 工作区 | 面向用户的功能 |
| --- | --- |
| 系统搭建 | 添加后端、查看能力、配置设备、保存应用 |
| 任务编排 | 设计业务层级状态机与行为树，关联 Entry、Do、Exit 和独立任务参数 |
| 运行调试 | 确认就绪、检查任务条件、执行、取消与安全停止 |

项目管理、导入导出和设置作为辅助入口，开发者可以展开高级区域查看接入协议和配置原始数据

## 后端接入边界

框架能依据符合契约的接入描述生成参数表单和能力节点，但不会从任意 ROS2 驱动或 SDK 自动推导执行接口

没有现成适配器时，需要先开发并部署执行适配器，导入描述文件本身不会安装驱动或授权真实设备

系统安全控制模式、业务层级状态机与任务行为树分层，行为树调用能力接口，不直接代替机械臂、底盘或 MCU 的实时控制与设备保护

## 目录

| 路径 | 内容 |
| --- | --- |
| `gui/` | Electron 桌面工作台 |
| `src/agro_runtime/` | 配置、任务、安全门控、运行与诊断 |
| `adapters/` | 可部署的执行适配器与模拟实现 |
| `contracts/` | 接入能力和执行协议 |
| `task_engine/` | BehaviorTree.CPP 任务引擎 |
| `examples/tomato_picker/` | 可选番茄采摘示例 |
| `docs/` | 架构与操作说明 |

详细架构见 [架构说明](docs/architecture.md)
