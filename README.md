# AT-System-Integration

独立的 ROS 2 系统集成软件，用于接入子系统、创建可复用任务，再用层级状态机和行为树组织工作流，适合熟悉 ROS 2 的机器人开发者

机器人名称、接口、启动配置、计算扩展与业务流程由外部机器人工程提供；本软件不内置具体机器人或作业策略

你可以离线读取接口、填写任务参数和编排流程；运行时由工作台准备所需环境、启动模块并执行工作流，重试、并行和多步骤子流程可用行为树组合

## 安装与启动

在 Ubuntu 桌面准备 Python、Node.js、npm、CMake、C++ 编译环境、libcurl 开发包和 Electron 图形依赖

进入本仓库目录，依次执行

```bash
./install.sh
./launch.sh
```

已有机器人工程时，可以直接打开它的目录

```bash
./launch.sh --profile /absolute/path/to/robot-profile
```

打开工程用于恢复已保存的配置；准备好配置后，在运行台确认设备环境并开始运行，工作台才会准备子系统和工作流

若移动了软件仓库，启动时提示安装目录不匹配，在新位置重新执行 `./install.sh`

## 先认识四个对象

| 对象 | 你在这里保存什么 |
| --- | --- |
| 机器人工程 | 机器人的子系统配置、任务、状态机、行为树和工程资源 |
| 子系统 ROS2 工作区 | 机械臂、视觉等子系统的接口定义，以及运行环境和启动来源 |
| 任务 | 一次业务调用的参数、输入输出、完成条件和停止方式 |
| 工作流 | 任务的执行顺序、状态转换和数据传递，主流程使用层级状态机，组合行为可使用行为树 |

机器人工程与软件仓库分开存储，工程目录包含 `robot.json` 和 `assets/`；子系统源码保留在各自工作区中

## 完成第一次集成

1. **创建或打开工程** — 点击顶部机器人选择器，新建机器人并选一个空目录；已有工程选择包含 `robot.json` 的目录
2. **接入子系统** — 在「机器人 → 子系统 ROS2 工作区」添加源码工作区、安装目录或接口文件，查看接口定义、运行环境和启动来源摘要，再展开需要补充的配置
3. **创建任务并编排** — 从已解析的通信接口创建任务，或在任务库手动新建；填写参数与输入输出，保存后在状态编排中设置初始状态、绑定行为并连接转换
4. **检查并运行** — 保存流程并点击「校验」，在诊断区域处理问题；进入运行台选择工作流，按运行准备中的缺项完成配置，再确认设备环境并开始运行

运行台会按需检查并加载子系统环境，再按依赖启动所需模块；各子系统使用独立进程中的环境，需要指定 setup 或 Python 时在对应工作区配置

启动来源支持节点、组件、普通程序和已有 launch，也可为任务选择使用外部已启动接口；详细步骤见 [工作台使用指南](docs/interactive-guide.md)

## 配置时最常用的几个概念

**接口类型与通信名称** 分别决定消息结构和调用位置，例如 `robot_interfaces/action/MoveArm` 描述参数与结果，`/arm/move` 是实际 Action 名称；名称可从源码与启动配置离线扫描，动态名称需补充配置，在线接口查看用于核对实际运行情况

**消息字段与业务含义** 根据接口定义生成参数表单，字段注释、常量和补充元数据帮助解释含义；`command_type` 等自定义字段的取值按子系统作者的定义填写

**任务输入输出与流程变量** 用于连接上下游任务，映射时核对类型、单位、坐标系和时间信息；数据路径说明可查看字段与变量的对应关系，行为树需声明根树输出端口并映射到黑板，成功后导出给外部流程

**初始子状态** 决定进入父状态后先执行哪个子状态，每个父状态独立指定；同级列表排序用于展示，初始选择保留原设置

状态的「进入时」「状态期间」「离开时」可以分别绑定任务或行为树，持续行为结束后产生成功或失败事件；普通状态可等待事件，结束整个流程时使用成功终态或失败终态

## 完成与停止

| 任务方式 | 什么时候完成，如何停止 |
| --- | --- |
| 发布一次话题消息 | 发送后完成，设备动作的完成情况需另有反馈确认 |
| 持续发布话题消息 | 持续运行，退出状态或取消时停止发布，并按配置发送停止消息 |
| 等待话题消息 | 收到满足条件的消息后完成，超过等待时限则超时 |
| Service | 收到响应并检查业务条件；声明为只读的服务可取消本地等待，设备操作需要配置停止核对 |
| Action | 等待最终结果并检查业务条件，取消时核对终态和配置的停止反馈 |

Service 与 Action 的停止核对服务应在确认设备或业务操作结束后返回成功；工作台据此确认停止并释放对应资源

遇到结果未知或停止待确认，在运行台核对设备状态；跨会话恢复还需核对旧执行进程，完成确认后再继续操作

设备和控制器负责急停、通信失联保护及实时控制，工作台负责模块、任务、数据与流程的组织和运行观察

## 保存与迁移

移动机器人工程时保留整个目录，在目标位置重新打开；通过机器人管理中的「工程依赖与资源」修正外部路径，并准备目标主机上的子系统依赖

`.agrobot.json` 用于旧工程导入和配置交换，入口位于「导入旧工程文件」；导入后核对行为树引用，日常使用直接打开工程目录
